# 评价模块更新说明

## 1. 更新目的

本次更新针对旧版六指标评价实现中存在的采样频率不一致、统计对象不一致、缺失值被误记为 `0`、燃油单位兼容性不足等问题进行修正。

六个官方评价指标的名称和优化方向保持不变：

1. 平均行程时间（越低越好）；
2. 平均等待时间（越低越好）；
3. 平均排队长度（越低越好）；
4. 通行能力（越高越好）；
5. 平均决策延迟（越低越好）；
6. 燃油强度（越低越好）。

本次更新只修改算法侧评价与后处理逻辑，没有修改 SUMO 路网、信号配时、路线文件或仿真核心代码。

对比基准：

- 旧版评价提交：`a632ee6`；
- 当前评价提交：`a6777e2`。

## 2. 当前六指标统计口径

### 2.1 平均行程时间

使用 TripInfo 中已完成且未被 `vaporized` 的车辆：

\[
\overline{T}_{travel}=\frac{1}{N_{arrived}}\sum_{v=1}^{N_{arrived}}duration_v
\]

TripInfo 提供真实的出发、到达和行程持续时间，避免把算法 `/step` 回调中车辆的“首次出现到消失”误认为完整行程。

### 2.2 平均等待时间

同样使用 TripInfo 中已完成车辆的 `waitingTime`：

\[
\overline{T}_{wait}=\frac{1}{N_{arrived}}\sum_{v=1}^{N_{arrived}}waitingTime_v
\]

TripInfo 已完成车辆数量必须与 `/finish` 的 `arrived_vehicles` 一致，否则该指标返回 `N/A` 并给出告警。

### 2.3 平均排队长度

通过只读高频观察器采集所有受控路口的进口车道 `halting_count`。每个观察帧先计算进口车道平均排队，再对全部时间帧求均值：

\[
\overline{Q}=\frac{1}{T}\sum_{t=1}^{T}
\left(\frac{1}{|L_{in}|}\sum_{l\in L_{in}}haltingCount_{l,t}\right)
\]

正式评价默认每 1 秒采样一次。评价频率独立于算法决策周期，避免 5 秒决策算法和 15 秒决策算法因为采样频率不同而产生不公平结果。

### 2.4 通行能力

使用 `/finish` 的最终到达车辆数和统一评价时长：

\[
Throughput=\frac{N_{arrived}}{T_{eval}}\times3600
\]

单位为 `veh/h`。

### 2.5 平均决策延迟

使用 `perf_counter` 统计控制器一次纯算法决策的耗时，不包含 SUMO 仿真推进、TraCI/HTTP 通信、日志和文件写入：

\[
\overline{L}=\frac{1}{K}\sum_{k=1}^{K}L_k
\]

Fixed 没有算法决策过程，因此记为 `N/A`，而不是虚假的 `0 ms`。

### 2.6 燃油强度

只统计使用燃油的车辆类型：

- `gasoline`；
- `diesel`；
- `hybrid`。

纯电动车、电动自行车及其他非燃油交通参与者不进入燃油指标的分子和分母：

\[
FuelIntensity=
\frac{Fuel_{fuel\ vehicles}/1000}
{Distance_{fuel\ vehicles}/100000}
\quad(L/100km)
\]

分子和分母使用完全相同的燃油车辆集合，并同时覆盖仿真结束时已完成和仍在路网中的燃油车辆。

评价器会自动检测本机 SUMO 版本，兼容 SUMO 1.14 前后燃油遥测单位变化；解析 emission 输出时会结合步长、燃油密度和车辆动力类型进行换算。

## 3. 相比旧版的主要修正

| 项目 | 旧版行为 | 当前行为 |
|---|---|---|
| 行程时间 | 用车辆首次出现到消失近似 | TripInfo 精确回填 |
| 到达判断 | 车辆从当前帧消失即视为到达 | 核对区间到达数、最终到达数和 TripInfo |
| 等待时间 | 使用消失前最后一个稀疏快照 | 使用 TripInfo `waitingTime` |
| 排队车道 | 遍历接口中的全部车道，可能包含出口车道 | 只统计初始化元数据声明的进口车道 |
| 排队采样频率 | 与控制器决策周期绑定 | 独立的统一高频观察器 |
| 决策延迟 | 缺失时默认显示 0 | 纯算法计时；缺失显示 `N/A` |
| 燃油统计集合 | 总燃油和已到达车辆距离可能不匹配 | 同一燃油车辆集合的燃油与里程 |
| 非机动车/电动车 | 未可靠过滤 | 根据 `powertrain` 排除非燃油车辆 |
| SUMO 燃油单位 | 固定按单一单位解释 | 自动兼容 SUMO 1.14 前后单位 |
| 缺失数据 | 默认值 `0`，可能被误认为性能最好 | 返回 `None/N/A` 并记录原因 |
| 数据来源 | 结果中无法追踪 | 每项指标写入 `metric_sources` |
| 数据完整性 | 无丢帧和时序检查 | 检查丢帧、重复帧、时间倒退及计数不一致 |

## 4. 文件作用

### `collector.py`

负责从 Protocol 2.0 的 `initialize`、`step`、`finish` 数据中实时采集：

- 进口车道排队；
- 到达/出发总数；
- 纯算法决策延迟；
- 分动力类型的逐车燃油和里程；
- 观察帧完整性及告警。

无法证明数据完整时，不再生成看似正常的数值，而是返回 `N/A`。

### `metrics.py`

负责评价后处理：

- 从 TripInfo 计算已完成车辆行程时间和等待时间；
- 将 TripInfo 精确指标回填到实时评价结果；
- 解析 emission 文件并修正燃油单位；
- 输出文本和 Markdown 六指标对比表。

### `observer.py`

统一的只读高频评价观察器。它只读取已有仿真帧，不发送信号控制动作，不改变 SUMO 行为。

### `runtime.py`

为进程内控制器维护每个 episode 的评价状态，负责：

- 启动与结束 collector；
- 在高频观察帧和决策帧之间避免重复采样；
- 校验 `episode_id`；
- 保存最后一次完整结果；
- 支持重复 `finish` 的幂等处理。

### `test_evaluation.py`

覆盖以下回归场景：

- 只统计进口车道；
- 汽油、柴油、混动车计入燃油，电动车排除；
- 已完成和活动燃油车辆使用相同统计集合；
- SUMO 1.14 前后燃油单位兼容；
- TripInfo 精确回填；
- 到达车辆观测不完整时返回 `N/A`；
- 高频观察器丢帧后的指标失效保护；
- 缺少辅助输入时不再填充虚假 `0`。

## 5. Fixed 与两套 MaxPressure 的统一对比

### 5.1 实验配置

为验证新评价口径，三种控制器在完全相同的仿真设置下进行配对测试：

- 路口：`demo_1` 至 `demo_20`，共 20 个路口；
- 交通时段：`off_peak`；
- 仿真时长：300 秒；
- SUMO 步长：0.05 秒；
- 高频评价观察间隔：1 秒；
- 外层控制回调间隔：5 秒；
- 最小绿灯：5 秒；
- 配对种子：`62001`、`62002`、`62003`、`62004`；
- 每种方法 4 次，共 12 次仿真；
- 三种方法共用同一套当前评价器；
- 所有 12 个任务均正常完成，无 worker 失败。

被测控制器版本：

- **Fixed**：SUMO 场景中的原始固定配时；
- **项目 MaxPressure**：历史 CoSLight 容量归一化密度压力控制，内部联合决策间隔 15 秒，控制器 SHA-256 为 `c350ee6b31370209deca84bd50622f1b9e562eb2fd98610bef8e3f0ede3d9391`；
- **学姐 MaxPressure**：`backend/app/controllers/max_pressure.py` 的 movement/halting pressure 实现，Git 提交 `2df19c3ac3bda831d1dbec3a5c2f50f216f4b652`，Git blob `56374ee198f70c70e85aaf10b0bd5ffc1d6969a0`，决策间隔 5 秒。

### 5.2 六大指标结果

|---|---:|---:|---:|---:|---:|---:|
| Fixed | 103.04 ± 0.17 s | 16.22 ± 0.11 s | 0.220 ± 0.000 veh | 744 ± 0 veh/h | N/A | 14.695 ± 0.015 L/100km |
| 项目 MaxPressure | 101.18 ± 0.37 s | 10.63 ± 0.40 s | 0.098 ± 0.004 veh | 885 ± 5 veh/h | **0.950 ± 0.027 ms** | 13.825 ± 0.009 L/100km |
| **学姐 MaxPressure** | **100.61 ± 0.47 s** | **7.37 ± 0.24 s** | **0.053 ± 0.004 veh** | **933 ± 5 veh/h** | 2.550 ± 0.025 ms | **13.613 ± 0.016 L/100km** |

这些指标不属于六大官方指标，仅用于检查 300 秒截断时仍在路网中的车辆，避免只观察已完成车辆造成误判。

## 6. 结果解释与边界

本次结果说明：在当前 20 路口、平峰、300 秒场景中，学姐当前仓库版本的 MaxPressure 明显优于 Fixed，也优于项目历史 MaxPressure。

这不等同于复现学姐过去使用旧 evaluation 得到的历史结果。历史结果还可能受到以下因素影响：

- 使用了不同版本的 MaxPressure 控制器；
- 控制器未通过正确入口接入；
- 相位动作编号、最小绿灯或回调间隔不同；
- 老版排队与燃油统计存在偏差；
- 测试场景、时长和随机种子不同。

但是，本次学姐 MaxPressure 的平均到达数为 77.75，Fixed 为 62；该数值来自统一 `/finish` 总数，不依赖 TripInfo 近似或排队统计。因此，学姐当前控制器在本场景中真实提高了车辆通行，而不是仅由新版评价器“算得更好”。

当前实验仍有以下边界：

- 只覆盖 `off_peak`；
- 每种方法只有 4 个 seed；
- 仿真时间只有 300 秒；
- 大量车辆在 episode 截止时仍处于路网中。

正式综合结论还应在 morning peak、evening peak、不同需求与扰动场景中，使用更长时间窗和更多配对 seed 复验。

## 7. 使用原则

后续 Fixed、SOTL、MaxPressure、IPPO、MAPPO 和 CoSLight 应统一遵守：

1. 六指标定义不随算法改变；
2. 前两项由 TripInfo 精确回填；
3. 排队使用统一频率的进口车道观察数据；
4. 延迟只测算法计算；
5. 燃油只统计燃油车辆，分子分母车辆集合一致；
6. 缺失或不完整数据必须显示 `N/A`，不能用 `0` 代替；
7. 对比实验使用配对场景和配对 seed，并报告均值、标准差及必要的截断诊断指标。
