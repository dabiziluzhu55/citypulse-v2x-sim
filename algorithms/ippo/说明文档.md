### 2026-07-31：IPPO v5a 局部压力奖励

- v5a 从零训练，不兼容 v4 checkpoint；checkpoint 中写入 `model_version=v5a` 和奖励定义，防止误续训旧模型。
- 每个路口在一次实际动作生效窗口内使用以下奖励：

  ```text
  r = -0.60 D + 0.20 F_safe - 0.15 B + 0.05 H
  D = 0.45 L + 0.40 S + 0.15 Qmax
  ```

- `L` 是车辆实时 `time_loss_s` 增量，`S` 是停车车辆秒数，`Qmax` 是最拥堵进口车道的容量占比；三者都按实际观测时长和物理车道容量归一化。
- `F_safe` 通过车辆“下一路口”在相邻观测间的变化推断过线流量，并按出口剩余空间折减；参考流量使用每条同时放行进口车道 `0.5 veh/s` 的饱和流率。
- `B` 是出口溢出风险：SUMO 的 occupancy 输入是 `0..100` 百分数，先除以 100；70% 以下不罚，70% 到 90% 二次增长，90% 以上封顶。
- `H` 保留进口累计等待的下降量，但只占 5%，用于平滑学习，不再作为唯一主目标。
- 奖励在物理量层面固定归一化并裁剪到 `[-3, 1]`，移除了会随训练历史漂移的动态 reward RMS。
- 状态末尾新增三个本路口出口摘要：平均 occupancy、最大 occupancy、最大出口停车/容量比。它们仍是路口本地信息，因此算法保持 IPPO，不引入全局 critic。
- 每个 transition 保存 `D/L/S/Qmax/F_safe/B/H`，PPO 日志输出主要分量，便于判断梯度改善究竟来自通行、排队还是溢出控制。
- v5a 不启用硬交通动作掩码、不引入下游多跳状态，也不修改 SUMO、路网、routes 或信号安全控制器；实时字段全部来自项目既有算法协议。
- 并行训练支持 `--periods`，按 seed 在 `morning_peak/off_peak/evening_peak` 间确定性轮转；12-worker 时每个 policy batch 恰好包含每种时段 4 个回合。checkpoint 保存 `training_periods`，错误时段组合不能直接续训。
- 三时段元数据检查发现 `demo_4` 的平峰相位为 `[1,2,3]`，早/晚高峰为 `[1,2,3,4]`。训练器只允许这种“同序尾部相位缺省”，并继续使用 transition 自带的 `valid_action_count` 掩码；任何相位重排、路口集合或进出口车道布局变化都会丢弃整个 policy batch。

#### 新增配对评估器

- `algorithms/ippo/evaluate_paired.py` 支持 `fixed/random/model`，对相同 seed 并行运行并汇总 SUMO 终点快照与 TripInfo 的 completed/unfinished/all-vehicle 指标。

##### 长时域/未完成车辆统一口径（2026-08-04）

全部评价器（CoSLight/IPPO/MAPPO）统一由 `simulation/sumo/tripinfo.py` 的 `parse_tripinfo_diagnostics()` 解析 tripinfo.xml（`write-unfinished=true`）：

- `unfinished_trips` = TripInfo 残余车辆（`arrival < 0`，含 `vaporized="end"`），权威残余计数；
- `end_waiting_total_s`（= `all_waiting_total_s`）= 全部已出发车辆（完成 + 未完成）累计 waiting，统一 end waiting 主口径；
- `end_waiting_mean_s` = `end_waiting_total_s / trip_records`，按已出发车辆平均；
- `residual_mismatch = unfinished_trips - remaining_vehicles` 交叉校验端末快照 `remaining`；非零表示需求触及窗口边界（未出发车辆）或计数异常，报告须告警；
- 端末瞬时 `waiting` 仅作诊断，不作为 end waiting 主口径。
- 本次没有修改 SUMO 程序、路网、routes、信号灯逻辑或 CoSLight 代码。路口 891 的既有 `Missing green phase` 警告在完整网络中仍会出现，由 SUMO 数据侧处理；所有对照方法使用同一网络，因此不改变本轮 paired comparison 的方向。

### 2026-08-01：IPPO v6 相位语义与防锁相修复

#### 边界与目标

- v6 是从零训练的纯 IPPO/RL 基线，不使用 MaxPressure 行为克隆、教师损失、logit prior 或残差动作。MaxPressure 只用于独立验收对照。
- 本轮仅修改 `algorithms/ippo/` 下的策略网络、采样、检查点、评估与测试；没有修改 SUMO、路网、routes、信号安全逻辑或 CoSLight。
- 为了隔离变量，v6 首轮仍使用 v5a 奖励 `-0.60D + 0.20F_safe - 0.15B + 0.05H`，先单独验证策略表示和执行链修复。

#### 确认的主要病因

- v5a 的共享 Actor 直接输出固定下标的 action logits，但不知道每个 action 实际服务哪些车道和 movement。异构路口中的“动作 0”并不具有统一交通语义，共享 Actor 容易学到错误的 action-index 偏置。
- v5a 没有最大绿灯/相位饥饿保护。弱小的 logit 偏置在 stochastic 采样中不一定致命，却会被 deterministic/argmax 放大成长期保持同一相位。
- 同一 v5a ep12 checkpoint、同一 `62001..62004` 评估中，deterministic 为 `arrived=59.50`、结束等待 `31652.55s`；stochastic 为 `arrived=67.75`、结束等待 `1633.41s`。这个巨大差异证明核心问题不是单纯“训练量太少”，而是 argmax 下的动作语义偏置和锁相。
- v5a 在 20 路口上持续出现 `B=0` 与 `H≈0`，这是奖励的次级问题；它需要单独做奖励消融，不与本次结构修复混在一起。

#### v6 算法修改

- Actor 改为共享的 candidate-phase scorer：先编码本路口状态，再对每个候选相位使用同一个 MLP 独立打分，而不是让网络学习固定 action index 的含义。
- 每个候选相位具有 9 个对齐特征：进口密度、停车密度、等待、出口密度、出口 occupancy、pressure、当前相位标记、未服务时间、名义绿灯时长。相位到 `(from_lane,to_lane)` 的映射来自现有算法 metadata。
- 使用布尔 action mask 同时屏蔽 padding action 和超时当前相位。多相位路口的最大绿灯为 `max(60s, nominal_green×2)`；单相位路口不会被错误地 mask 成无动作。
- rollout 保存决策时的 phase features 和完整 action mask，PPO 重算 log-prob 时使用同一份数据，保持 on-policy 概率口径一致。
- 新增执行链诊断：命令数、切相请求数、观测到的实际切相数、生效延迟、未解决命令、最大绿灯强制次数、每路口相位选择分布和相位支配率。数据源是后续实时相位观测，不依赖 TripInfo。
- 并行 worker 元数据一致性检查现在同时比较相位的 movement 映射和绿灯时长，不再只比较相位编号和车道列表。
- checkpoint 版本升为 `v6`，额外保存 `phase_feature_schema` 和 `max_green_factor`；v5a checkpoint 会在启动 SUMO 前被拒绝，不会静默误载。

#### 测试与 4 路口 smoke

- 新增候选相位置换等变性、movement 对齐特征、布尔 mask、最大绿灯、单相位边界、动作执行链、旧 checkpoint 拒绝和并行 metadata 漂移测试。
- `python3 -m pytest -q algorithms/ippo` 结果为 `52 passed`。
- 4 路口、4 worker、4 episodes、120 仿真秒 smoke 得到 128 条样本，`pending_dropped=0`；各回合实际/请求切相为 `21/21、24/24、20/20、18/18`，未出现动作被接口吞掉。

### 2026-08-01：IPPO v6b 区域队列与吞吐对齐奖励

#### 修改原因与公式

- v6 已修复动作语义和锁相，但 ep16→ep32 的配对结果证明 v5a 奖励与全过程等待/吞吐不完全对齐。v6b 因此只替换奖励，保留已验证的 candidate-phase Actor、action mask、PPO 和执行链。
- v6b 从零训练，不兼容 v6 checkpoint，不引入 MaxPressure 教师：

  ```text
  r = -0.50 Q_region - 0.15 L + 0.25 F_safe - 0.05 B - 0.05 C_switch
  Q_region = Q_local + 0.25 * mean(Q_downstream_neighbors)
  ```

- `Q_local` 是一次实际动作窗口内的本路口停车辆秒，按进口物理容量和观测时长归一化；`Q_downstream_neighbors` 是 metadata 已有下游相邻路口的同口径停车队列。
- `L` 是实时车辆 `time_loss_s` 增量，`F_safe` 是按出口回溢风险折减的过线量，两者分别对齐全程 timeLoss 和吞吐。
- `B` 保留出口回溢风险；`C_switch` 只惩罚相位时长低于 30 秒时的过早切相，30 秒后切相不罚，保持信号稳定而不鼓励长期锁相。
