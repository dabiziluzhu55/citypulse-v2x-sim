# Cooperative MAPPO（faithful v1）说明文档

> 本目录实现论文忠实的 Cooperative MAPPO（`cooperative_joint_v1`），是算法端
> 唯一交付版本。v2 / M1 / v1.1-AS（owner-conditioned）等分支已移除。

## 1. 算法概述

Cooperative MAPPO 与 IPPO 的区别在于：所有受控路口在**同步 joint step** 中联合决策，
共享**团队奖励**，并使用能看到全局状态的**集中式 Critic** 逼近团队回报。

- 决策：每个 `action_interval`（默认 15 s）所有路口同时产生目标相位；
- 奖励：每个路口计算 v5a 局部奖励，团队奖励 = clip(mean(局部奖励), -3, 1)；
- Critic：`IsomorphicTeamValueCritic` 对全局状态做同构 pooling，
  `critic-scope=global` 输出一个标量团队价值并广播给所有 owner；
  `critic-scope=local` 每个 owner 输出自己的价值（仍是团队回报目标）；
- 训练目标：共享 Actor 的 PPO，GAE（gamma=0.99，lambda=0.95）基于团队价值；
- 完整 joint 约束：一个 joint 内所有 agent 的相位应用都必须被确认，
  finish 时未确认/未观测完整的 joint 会使整个 worker 无效（不丢弃部分数据）。

## 2. 配置（`config.py`）

关键默认值：

| 字段 | 默认值 |
|---|---|
| `model_version` | `cooperative_joint_v1` |
| `critic_scope` | `global`（可选 `local`） |
| `reward_scope` | `shared_team` |
| `critic_target_scope` | `team_return` |
| `team_reward_schema` | `v5a_team_mean_raw_then_clip_v1` |
| `joint_step_schema` | `synchronized_all_intersections_v1` |
| `action_interval_s` | 15.0 |
| `hidden_dim` | 128 |
| `gamma` / `gae_lambda` | 0.99 / 0.95 |
| `ppo_clip` / `entropy_coef` | 0.2 / 0.01 |
| `ppo_epochs` / `minibatch_size` | 4 / 128 |
| `actor_lr` / `critic_lr` | 3e-4 / 1e-4 |

`algorithm_label`：
- `shared_team` + `global` → `cooperative_mappo`
- `shared_team` + `local` → `cooperative_ippo`

## 4. 训练

```bash
python3 -m algorithms.mappo.train \
  --model-version cooperative_joint_v1 --critic-scope global \
  --intersections 20 --episodes 160 --workers 8 --duration 300 \
  --base-seed 95501 --period off_peak --checkpoint-every 20 \
  --save algorithms/mappo/runs/cooperative_mappo_20tls.pt
```

- `--init` 仅支持 `random`（从零训练，不做行为克隆/warm start）；
- `--resume` 支持从 checkpoint 续训（校验 generation/optimizer/RNG 完整恢复）；
- 默认保存到 `algorithms/mappo/runs/{algorithm_label}_{n}tls.pt`。

## 5. 评估

```bash
python3 -m algorithms.mappo.evaluate_checkpoint \
  --checkpoint algorithms/mappo/runs/cooperative_mappo_20tls.pt \
  --seeds 66501 66502 66503 66504 66505 66506 66507 66508 \
  --workers 8 --duration 300 --period off_peak \
  --output algorithms/mappo/runs/evaluation.json
```

评估使用未参与训练的 held-out seed、确定性推理，并记录六项正式指标
（行程时间、等待时间、排队、吞吐、决策延迟、油耗）及完成率/未完成统计。

## 8. 兼容性与边界

- `MAPPOPolicy` 保留 `residual_hidden_dim` / `residual_init_seed` 构造形参以兼容
  外部 `traffic_control/mappo/controller.py` 调用，但实现中已忽略（无 residual 分支）。
- 旧版本地奖励 checkpoint 可读取元数据（`read_checkpoint_metadata`），但不能恢复为
  cooperative 架构训练状态。
- 算法端只维护 `algorithms/mappo`；不修改其他组代码、SUMO 路网/routes/tlLogic、
  后端或评价口径。不 push GitHub main。
