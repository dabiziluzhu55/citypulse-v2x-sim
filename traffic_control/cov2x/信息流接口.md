# CoV2X 车路云协同算法 · 信息流接口文档

- 版本：v1（2026-08-11）
- 适用范围：`traffic_control/cov2x`（EP12 车路云三端联合初版，唯一部署形态）
- 接口定义方：算法组（本仓库即权威定义，不再依赖外部标准）

## 1. 总体结构

```
                 ┌─────────────── 云端 Cloud Actor（15s 决策）──────────────┐
                 │  per-intersection priority: relax / neutral / boost      │
                 └───────────────┬───────────────────────┬──────────────────┘
                                 │ cloud_priorities      │
                                 ▼                       ▼
        ┌─────────────── 路端 Signal Actor（15s 决策）───────────────┐
        │  固定相序 keep/advance，输出 target_phase                  │
        └───────────────┬───────────────────────┬──────────────────┘
                        │ phase_intents         │
                        ▼                       ▼
        ┌─────────────── 车端 Vehicle Actor（5s 决策）───────────────┐
        │  进口道 approach advisor：lane + speed，输出车速/车道建议    │
        └────────────────────────────────────────────────────────────┘
```

三端共享同一个 centralized critic（训练期使用），执行期各自独立推理，通过
Protocol 2.0 字典接口与 SUMO/前端对接。路端只输出目标相位，黄灯/清空等过渡
由仿真器负责。

## 2. 协议基础（Protocol 2.0）

算法模块通过 `algorithm_module="traffic_control.cov2x"` 被 SUMO 本地调用，
模块必须暴露三个函数：

| 函数 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `initialize(payload)` | 场景元数据 | `{protocol_version, episode_id, ready: true}` | 建立静态索引、加载 EP12、记录三端状态 |
| `step(payload)` | 单步全量观测 | `{protocol_version, episode_id, step_id, actions}` | 返回路端+车端动作 |
| `finish(payload)` | 收官观测 | 无 | 结算/复位运行时状态 |

校验规则（由 `simulation/sumo/policy_transport.py` 强制）：

- `initialize` 必须回显 `episode_id` 且 `ready=true`；
- `step` 必须回显 `episode_id` 与 `step_id`；
- `step.actions` 必须**恰好**包含 `signals` 与 `vehicles` 两个对象。

## 3. 三端角色、决策周期、观测与动作

### 3.1 车端（Vehicle Actor）

- 决策周期：5s（跟随协议回调 `decision_interval=5.0`）。
- 角色：每个进口道一个 approach slot（共享同一组策略参数）。
- 观测：41 维 lane state + 3 维云端优先级 one-hot（合计 44 维）。
- 动作：
  - `lane_action ∈ {0 keep, 1 left, 2 right}`；
  - `speed_bin ∈ {0.00, 0.25, 0.50, 0.75, 1.00}` 乘以 `allowed_speed_mps`。
- 输出格式：

```json
"vehicles": {
  "veh_001": {"target_speed_mps": 10.4, "target_lane_index": 2}
}
```

### 3.2 路端（Signal Actor）

- 决策周期：15s（`signal_decision_interval_s=15.0`，中间回调保持上一决策）。
- 角色：每个受控路口一个逻辑 agent（共享参数）。
- 观测：37 维（8 进口道 × 3 特征 + 8 相位 one-hot + 2 计时特征 + 3 云优先级）。
- 动作：`{0 keep 当前相位, 1 advance 到相序下一相位}`，再由固定 `phase_order`
  映射为 `target_phase`。不允许任意跳相。
- 输出格式：

```json
"signals": {
  "demo_1": {"target_phase": 2}
}
```

### 3.3 云端（Cloud Actor）

- 决策周期：15s（EP12 checkpoint 配置 `cloud_decision_interval_s=15.0`；
  算法端默认配置为 30s，以 checkpoint 内冻结配置为准）。
- 角色：网络级单槽策略，为每个受控路口输出 3 类优先级。
- 优先级语义：`0=relax`（放松）、`1=neutral`（中性，默认）、`2=boost`（提升）。
- 落点：云优先级 one-hot 会注入路端观测与车端观测，并进入 centralized critic；
  **不通过 `step.actions` 直接返回**（协议只承载 signals/vehicles），
  外部如需展示云端决策，可读取算法侧诊断或后续消息事件流（见 §6）。

## 4. 输入 payload 字段（step）

| 字段 | 类型 | 说明 |
|---|---|---|
| `protocol_version` | str | 固定 `"2.0"` |
| `episode_id` / `step_id` / `simulation_time` | str/int/float | 帧标识与仿真时钟 |
| `period` | str | `morning_peak` / `off_peak` / `evening_peak` |
| `intersections.<tls>.phase_order` | list[int] | 该路口固定相序 |
| `intersections.<tls>.current_phase` | int | 当前生效相位 |
| `intersections.<tls>.stage` / `stage_elapsed` | str/float | 灯色状态与已持续时间 |
| `intersections.<tls>.lanes.<lane>` | dict | 车辆数/排队/占用/速度/等待等 |
| `edge_lanes` | dict | 进口道/出口道静态几何与限速 |
| `vehicles.<vid>.motion` | dict | 速度/加速度/限速 |
| `vehicles.<vid>.location` | dict | 所在 edge/lane/位置/路线 |
| `vehicles.<vid>.next_signal` | dict | 下一路口与距离 |
| `vehicles.<vid>.leader_gap_m` | float | 前车间距 |
| `traffic` | dict | 全局活跃/驶离/到达/最小期望车辆数等 |
| `previous_action_results` | dict | 上一帧动作执行结果 |

## 5. 输出响应字段（step）

```json
{
  "protocol_version": "2.0",
  "episode_id": "...",
  "step_id": 3,
  "actions": {
    "signals": {"demo_1": {"target_phase": 2}},
    "vehicles": {"veh_001": {"target_speed_mps": 10.4, "target_lane_index": 2}}
  }
}
```

- `signals`：仅包含**本次 payload 实际受控路口**（子集场景安全规则，见 §9）。
- `vehicles`：仅包含有合法可执行建议的车辆；`off` 模式返回空对象。

## 6. 信息流消息定义（我方定义）

以下消息类型为本算法对外暴露的通信语义。当前 joint 模式下，消息通过
观测注入和动作输出在算法内部传递；后续如需前端实时展示，可据此字段产出
消息事件流（记录时间戳、来源端、目的端、载荷）。

| 消息 | 方向 | 周期 | 载荷字段 | 当前落点 |
|---|---|---|---|---|
| `vehicle_intent` | 车 → 路 | 5s | 预测到达、目标方向、延迟/排队证据、建议接受度 | 车端观测（lane state） |
| `road_phase_intent` | 路 → 车 | 15s | 当前相位、目标相位、剩余/预期时长、下游可用性 | `phase_intents` 注入车端观测 |
| `cloud_priority` | 云 → 路/车 | 15s | per-intersection priority（relax/neutral/boost） | one-hot 注入路端/车端观测 |
| `road_demand` | 路 → 云 | 15s | 聚合排队/压力/延误 | 云端观测（86 维全局状态） |
| `guidance_command` | 路 → 车 | 5s | 目标车速、目标车道 | `actions.vehicles` |

统一的推荐消息记录字段（前端展示约定）：

```json
{
  "ts": 123.4,
  "source": "cloud|road|vehicle",
  "target": "road|vehicle|cloud",
  "type": "cloud_priority",
  "payload": {...}
}
```

## 7. 部署模式与环境变量

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `COV2X_MODEL_ALIAS` | `cov2x_joint_ep12` | 场景默认模型别名 |
| `COV2X_MODEL_PATH` | 别名解析结果 | 显式覆盖 checkpoint 路径 |
| `COV2X_MODE` | `eval`（部署自动设置） | `train` / `eval` / `rule` |
| `COV2X_SIGNAL_MODE` | `learned`（部署自动设置） | `learned` / `max_pressure` / `fixed` |
| `COV2X_CLOUD_MODE` | `learned`（部署自动设置） | `learned` / `off` |
| `COV2X_VEHICLE_MODE` | `learned`（部署自动设置） | `learned` / `rule` / `off` |
| `COV2X_SIGNAL_DECISION_INTERVAL` | `15.0` | 路端决策周期（秒） |
| `COV2X_CLOUD_DECISION_INTERVAL` | `15.0`（EP12 冻结配置） | 云端决策周期（秒） |

  signal_action=2，cloud_priority_classes=3，max_intersections=20

## 9. 子集场景规则

- 受控路口以 `payload.intersections` 为准；EP12 在 east_dense / west_dense
  子集场景下只输出子集路口的路端动作，不会输出 checkpoint 中其他路口。
- 相位顺序以 **payload 的 `phase_order` 为执行权威**（对应 SUMO 该时段的
  信号程序；demo_4 在不同时段相位数不同，如 off_peak=3 / morning=4 /
  evening=4）。checkpoint 内 `phase_orders` 仅作训练记录，不会覆盖时段相序。

## 10. 前端展示建议

前端如需展示“通讯消息”，建议消费 §6 定义的消息事件流。算法侧当前通过
`controller.py::diagnostics()` 暴露模式、模型路径、决策计数等运行状态；
消息级事件流可作为下一迭代在算法端输出（不修改仿真侧），由本接口文档先行
固定字段格式。
